# Priority 6: feel features on his mechanical model, 2026-11-22

Maker's request (relayed by the main Izzy session): rebuild the live "feel" features from lower-timeframe
bars, then test which of them separate winners from losers in both halves. Simulation only; the live
strategy (v0.5) is unchanged.

## Engine
- Script: "Izzy P1 mechanical" v2.0 (`tools/pine/izzy_p1_mechanical.pine`). The rules are the same as v1
  (pure model, filters off). The only change is that every entry comment now records the feel features.
- Market: CME_MINI:MNQ1!, 5m, Deep Backtesting, in three windows: 2019-06→2022, 2023→2024, 2025→2026-11-21.
- Analysis: `tools/feel/feel_p1.py <trades.json>`.

## Features: definitions and lookahead
Every feature is measured on the inversion bar or earlier. The order fills at the next bar's open, so no
feature uses a bar that closes after the entry decision.

| Tag | Feature | How it is measured |
|---|---|---|
| x | cross timing | the minute (1–5) inside the 5m candle when a 1m close first lands beyond the gap edge (`request.security_lower_tf`); 1m data only from 2023-11-30 |
| f | flips | after that first cross, how many times a 1m close falls back across the edge |
| b | body % | candle body as % of its range |
| c | close location | % of the range from the far end (100 = closed at the extreme) |
| v | volume burst | candle volume ÷ average of the previous 20 candles |
| h | chop before | sum of the ranges of the previous 6 bars ÷ their combined high–low (high = overlapping) |
| rb / rp | reaction sharpness | bars and points from the sweep extreme to the inversion close |
| p | push-through | bars from gap creation to the inverting close |

## Read ~
1. **Cross timing is the one feature that holds.** Late crosses beat early ones in both sub-periods (2.19 vs
   0.67, then 1.05 vs 0.65). It is the opposite of the naive reading of "speed". When a 5m candle is already
   through the gap in its first minute, the move has stalled for four minutes by the time the candle closes.
   When it crosses at minute 4–5, the push is still running into the close. That fits "I like taking trades
   off speed" if speed means speed at the close, not at the open. ~ Small sample (63 late-cross trades),
   and the tertile cuts were chosen on this same data.
2. **Flips:** flips before the close were worse in both periods (0.63, 0.46), consistent with "can't jump the
   gun". But only 23 trades had flips. Direction yes, proof no.
3. **The finished-bar features (body %, chop, volume, reaction) do not hold.** Chop and body % reverse sign
   between halves, a textbook overfitting trap. This agrees with claim 10 (body % ✗).
4. **Combined score:** it ranks the trades in both periods (score 3 beats score < 3 every time). But in
   2025–26 it only lifts the model from losing to breakeven. On this model it is a filter, not an edge.

## Not done (and why)
- **P1 + filters subset:** only 94 trades in 2019–26, about 35 in the 1m era. That is too few to split by
  feature. The rule to carry over to it is the cross-timing rule, unchanged.
- **v0.4 max-1/day:** the lab script does not log these features yet. Next quota: add the same tag to the lab,
  then run max-1/day on 1m 2023-11→2026-11 to test cross timing out of sample on a second model.

## Decision ~
- **Cross timing** becomes a candidate feel rule for the forward test: prefer crosses in the last 40% of the
  entry candle. Live v0.5 already logs `cross_s`, so it can be checked on Bot's alerts without changing the
  strategy.
- No feel rule goes into the live strategy until it holds on v0.4 too and in the forward log.
